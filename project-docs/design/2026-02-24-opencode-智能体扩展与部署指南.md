# 扩展新智能体并打包部署指南

> **文档说明**：本文档说明如何在 oh-my-opencode 中添加新的智能体，以及如何进行打包和通过 CI 流水线部署发布。
> **适用版本**：oh-my-opencode v3.7+

---

## 第一部分：添加新智能体

### 1. 智能体架构

oh-my-opencode 的内置智能体遵循 Factory 模式：

```typescript
// 每个 Agent 对应一个工厂函数，接受 model 参数并返回 AgentConfig
// 此外，必须挂载静态的 mode 属性以声明其在 UI/后台 的行为模式
type AgentFactory = ((model: string) => AgentConfig) & { mode: AgentMode }

// AgentMode 有三种值：
// - "primary": 尊重 UI 选择的模型（如 sisyphus, atlas）
// - "subagent": 使用自己的 fallback chain，忽略 UI（如 oracle, explore）
// - "all": 可在两种上下文中使用
```

### 2. 创建智能体的步骤

#### Step 1: 创建智能体文件

在 `src/agents/` 目录下创建新文件，例如 `src/agents/myagent.ts`：

```typescript
import type { AgentConfig } from "@opencode-ai/sdk"
import type { AgentMode, AgentPromptMetadata } from "./types"
import { createAgentToolRestrictions } from "../shared/permission-compat"

const MODE: AgentMode = "subagent"

// 智能体元数据（用于生成 Sisyphus 的委托决策表、工具选择等）
export const MY_AGENT_PROMPT_METADATA: AgentPromptMetadata = {
  category: "utility",      // 必须是 "exploration" | "specialist" | "advisor" | "utility" 之一
  cost: "CHEAP",            // "FREE" | "CHEAP" | "EXPENSIVE"
  promptAlias: "MyAgent",
  triggers: [
    {
      domain: "特定领域",
      trigger: "触发该智能体的条件描述",
    },
  ],
  useWhen: [
    "使用场景 1",
    "使用场景 2",
  ],
  avoidWhen: [
    "不应使用的场景",
  ],
  keyTrigger: "关键触发词或模式，用于快速识别",
}

function buildMyAgentPrompt(): string {
  return `你是一个专门的智能体，负责...

## 身份
...
`
}

// Factory 函数
export function createMyAgentAgent(model: string): AgentConfig {
  // 定义权限：通过辅助函数安全生成 permission 配置
  const restrictions = createAgentToolRestrictions([
    "read",
    "grep_search",
  ])

  return {
    description: "简短描述智能体的功能 (MyAgent - OhMyOpenCode)",
    mode: MODE,
    model: model,
    temperature: 0.1,  // 大多数推理智能体使用低温度
    // maxTokens: 16000,  // 可选：控制最大输出 token，多数情况下框架有默认值
    // color: "#FF6B6B",  // 可选：UI 显示的特征色
    prompt: buildMyAgentPrompt(),
    ...restrictions,   // 展开工具权限配置 (将自动注入 permission 对象)
  } as AgentConfig
}

// 必须设置静态 mode 属性
createMyAgentAgent.mode = MODE
```

#### Step 2: 注册智能体

核心的内置智能体注册表位于 `src/agents/builtin-agents.ts`。所有新开发的内置智能体必须在此注册，无需在 `index.ts` 中手动导出 `AgentFactory`。

```typescript
// src/agents/builtin-agents.ts

import { createMyAgentAgent, MY_AGENT_PROMPT_METADATA } from "./myagent"

// 1. 添加到 agentSources
const agentSources: Record<BuiltinAgentName, AgentSource> = {
  sisyphus: createSisyphusAgent,
  hephaestus: createHephaestusAgent,
  oracle: createOracleAgent,
  librarian: createLibrarianAgent,
  explore: createExploreAgent,
  "multimodal-looker": createMultimodalLookerAgent,
  metis: createMetisAgent,
  momus: createMomusAgent,
  atlas: createAtlasAgent as AgentFactory,
  // ... 添加你的智能体
  myagent: createMyAgentAgent, 
}

// 2. 添加元数据
const agentMetadata: Partial<Record<BuiltinAgentName, AgentPromptMetadata>> = {
  oracle: ORACLE_PROMPT_METADATA,
  // ...
  myagent: MY_AGENT_PROMPT_METADATA,
}
```

#### Step 3: 补充类型定义

在 `src/agents/types.ts` 中扩展 `BuiltinAgentName` 的枚举类型：

```typescript
// src/agents/types.ts
export type BuiltinAgentName =
  | "sisyphus"
  | "hephaestus"
  | "oracle"
  | "librarian"
  // ... 其他现有项
  | "myagent"  // <- 添加这行
```

并在 `src/config/schema/agent-names.ts` 中同步 Zod 验证器的 schema：

```typescript
// src/config/schema/agent-names.ts
export const BuiltinAgentNameSchema = z.enum([
  "sisyphus",
  "hephaestus",
  "prometheus",
  "oracle",
  // ... 其他现有项
  "myagent",  // <- 添加这行
])
```

### 3. 配置模型回退链

如果在 `subagent` 模式下运行，智能体会通过配置的模型回退链来自动选择当前可用的模型。在 `src/shared/model-requirements.ts` 中添加你的智能体所需的回退链：

```typescript
// src/shared/model-requirements.ts
export const AGENT_MODEL_REQUIREMENTS: Record<string, ModelRequirement> = {
  // ...
  myagent: {
    fallbackChain: [
      { providers: ["anthropic"], model: "claude-sonnet-4-6" },
      { providers: ["openai"], model: "gpt-5-nano" },
    ],
    requiresAnyModel: true,
  },
}
```

### 4. 创建复杂的条件工厂（可选）

对于需要根据运行时环境（如已禁用的技能、可选的模型类别等）做复杂动态初始化的智能体（如 Sisyphus、Atlas 等），可以在 `src/agents/builtin-agents/` 目录下为其创建专用的条件初始化封装。

例如 `maybeCreateMyAgentConfig`：

```typescript
// src/agents/builtin-agents/my-agent-config.ts
import { createMyAgentAgent } from "../myagent"
import { AGENT_MODEL_REQUIREMENTS } from "../../shared/model-requirements"
import type { AvailableAgent, AvailableCategory, AvailableSkill } from "../dynamic-agent-prompt-builder"
import type { AgentOverrides } from "../types"

export function maybeCreateMyAgentConfig(input: {
  disabledAgents: string[]
  agentOverrides: AgentOverrides
  availableModels: Set<string>
  systemDefaultModel?: string
  isFirstRunNoCache?: boolean
  availableAgents: AvailableAgent[]
  availableSkills: AvailableSkill[]
  availableCategories: AvailableCategory[]
  mergedCategories: Record<string, any>
  directory?: string
  useTaskSystem?: boolean
  // ... 其他插件运行时上下文
}): AgentConfig | undefined {
  // 1. 检查用户的全局禁用状态
  if (input.disabledAgents.includes("myagent")) return undefined

  // 2. 检查模型要求与解析
  // (调用 model-resolution.ts 中的辅助解析逻辑找出最终模型)
  
  // 3. 构造基础 config 并与用户层 override 深度合并
  // ...
  
  return resolvedConfig
}
```

## 第二部分：打包和部署

由于 `oh-my-opencode` 包含 Native 依赖（如 `@ast-grep/napi`），并且会在多平台发布携带架构后缀的二进制文件，部署和发布流程已经完全集成到了 GitHub Actions 工作流中。

### 1. 本地构建与验证

在本地开发和调试时，可通过以下步骤构建和验证修改：

```bash
# 1. 安装依赖并自动触发 postinstall 钩子
bun install

# 2. 清理旧产物
bun run clean

# 3. 构建主包与 CLI 入口（生成 dist 目录，TSC 生成 d.ts 声明，构建 JSON Schema）
bun run build
# (内部执行: bun build src/index.ts ... && bun build src/cli/index.ts ... && tsc ... && bun run build:schema)

# 4. 执行全量类型检查
bun run typecheck

# 5. 运行所有的单元测试以确保正确性
bun test
```

### 2. 通过 GitHub Actions 自动发布

项目在 `.github/workflows/publish.yml` 中配置了一套完备的发布管道，不要在本地手工 `npm publish`：

1. **触发发布** (Workflow Dispatch)：
   进入 GitHub Actions 页面，手动触发 `publish` 流程，并指定提升版本级别 (`patch`, `minor`, `major`) 或填入特定版本号。
2. **并行测试与类型检查**：
   工作流会自动隔离执行重度依赖 Mock 状态的特殊测试，再执行剩余的绝大部分并行测试和类型检查。
3. **主包发布 (Main Package)**：
   自动计算版本，通过 `jq` 更新各个 `package.json`，构建主包及 Schema，使用 provenance 发布到 NPM，并自动打上包含正确版本号的 Git Tag，推送到远端 master 分支。
4. **多平台分发 (Platform Packages)**：
   主干包发布成功后，通过调用并行的 `publish-platform.yml` 任务，自动交叉构建 `darwin-arm64`, `linux-x64-musl` 等平台的特定二进制包。这保证了 OpenCode 在安装该插件时能够无缝拉取适用于当前主机的 Native 依赖包。

## 第三部分：用户配置覆盖

用户可以在配置文件中非常细粒度地调配已注册功能，插件配置的生效层级为：

1. **项目级配置**：`.opencode/oh-my-opencode.jsonc` （或 `.json`）
2. **全局用户配置**：`~/.config/opencode/oh-my-opencode.jsonc` （或 `.json`）

### 1. 覆盖覆盖智能体配置

可以使用驼峰名称设置诸如 `maxTokens`, `temperature` 等属性，以覆盖内置的智能体设定：

```jsonc
{
  "agents": {
    "myagent": {
      "model": "claude-sonnet-4-6",      // 强制覆盖使其使用指定模型
      "temperature": 0.2,                 // 覆盖采样温度
      "prompt_append": "额外需要注意...",   // 在内置系统提示词末尾追加
      "maxTokens": 32000                  // 修改推理阶段最大输出 Token 限制
    }
  }
}
```

### 2. 局部功能的开关配置 (Disable Flags)

除了对特定智能体进行参数微调外，也可通过各类 `disabled_*` 数组完全屏蔽部分功能：

```jsonc
{
  "disabled_agents": ["myagent", "metis"],      // 完全禁用所列出名称的智能体
  "disabled_mcps": ["github-mcp"],              // 禁用特定的 MCP 服务器
  "disabled_hooks": ["provider-toast"],         // 禁用某些副作用的生命周期钩子
  "disabled_commands": ["refactor"],            // 停用自带的 Slash Commands
  "disabled_skills": ["frontend-ui-ux"]         // 卸载不再需要的内置提示词能力包
}
```
