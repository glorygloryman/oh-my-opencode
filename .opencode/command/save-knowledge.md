# 保存会话为知识文档

将当前会话的对话内容总结为一份结构化的知识文档，保存到 `project-docs/FAQ/` 目录。

**标题来源**: 如果用户提供了 `$ARGUMENTS`，使用其作为主题主干；否则自动提取主题。

---

## 执行步骤

### 第一步：获取会话内容

1. 调用 `session_list()` 获取所有会话列表
2. 找到最近活跃的会话（即当前会话），获取其 `session_id`
3. 调用 `session_read({ session_id: "<当前会话ID>", include_todos: true })` 读取完整对话记录

### 第二步：内容过滤

在分析之前，必须对原始会话内容进行严格过滤：

**必须过滤的内容**:
- `<thinking>...</thinking>` 标签及其内部所有内容（模型思考过程）
- 工具调用原始输出块，包括：
  - `session_read` 返回的原始 JSON/结构化数据
  - `Bash` 命令的输出结果
  - `Read` 文件内容的原始输出
  - `Grep`、`Glob`、`LSP` 等工具的原始返回
  - 任何以 `[工具名] 结果：`或类似格式标记的原始输出
- Session ID、消息 ID 等技术标识符
- 调试日志、错误堆栈（除非是讨论的核心内容）
- 重复的试错过程（保留最终方案和关键决策点即可）

**主题相关性过滤** (仅当 `$ARGUMENTS` 不为空时):
- 用户指定的主题关键词：`$ARGUMENTS`
- 只保留与该主题**直接相关**的对话内容
- 过滤掉与主题无关的寒暄、过渡性语句、旁支讨论
- 如果某段对话与主题关联度低，可以忽略或简要提及

### 第三步：分析与总结

基于过滤后的内容，提取以下信息：

- **核心主题**：本次对话围绕什么问题展开
- **关键讨论要点**：经过了哪些分析、探索、决策
- **最终结论/方案**：得出了什么结果
- **涉及的关键文件/代码**：讨论中提到的重要文件路径

总结规则：
- 使用中文撰写全部内容
- 聚焦有价值的知识点和决策过程
- 保持简洁可读，篇幅控制在合理范围内
- 不要包含技术噪音

### 第四步：生成文件名

**标题确定**:
- 如果 `$ARGUMENTS` 不为空：使用 `$ARGUMENTS` 作为主题主干
- 如果 `$ARGUMENTS` 为空：根据对话内容自动提取主题（5-15字）

**文件名格式**: `YYYY-MM-DD-中文主题描述-HHMMSS.md`
- 日期使用当前日期
- 时间戳使用当前时分秒（HHMMSS，24小时制）
- 中文主题描述要简洁概括对话核心内容

**示例**:
- `2026-02-24-插件生成机制-143052.md`
- `2026-02-24-会话保存方案-095812.md`

### 第五步：写入文件

使用 Write 工具将文档写入 `project-docs/FAQ/` 目录（如目录不存在则创建）。

文档结构模板：

```markdown
# [中文标题，与文件名主题一致]

> 生成时间：YYYY-MM-DD HH:MM:SS
> 来源：OpenCode 会话总结
> 主题关键词：[如果 $ARGUMENTS 不为空，列出使用的关键词]

## 背景与问题

[描述本次对话的起因、要解决的问题或要实现的目标]

## 讨论要点

### [要点1标题]

[具体内容]

### [要点2标题]

[具体内容]

（根据实际讨论内容增减要点数量）

## 结论与决策

[最终得出的结论、选定的方案、关键决策及其理由]

## 相关引用

- [涉及的关键文件路径、代码片段、外部链接等]
```

---

## 约束

- 直接写入文件，不需要用户确认
- 文档语言必须为中文
- 标题和文件名中的主题描述必须为中文
- 如果 `$ARGUMENTS` 不为空，在文档顶部标注使用的主题关键词
- 如果对话内容过于简短或无实质内容，告诉用户没有值得保存的内容即可
- `project-docs/FAQ/` 目录如果不存在，需要先创建
- **完成写入后，向用户确认文件路径和标题**
